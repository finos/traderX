# Decisions and compatibility research

Reviewed 2026-11-22. See [live evidence](evidence/2026-11-22-live-baseline.md) for the verified reference deployment and bounded platform fixtures; the full hardened profile remains pending.

- **Profile placement:** use an opt-in directory inside State 012. This preserves the constitution's numbered spec ownership without reserving a permanent state ID.
- **Baseline:** generated snapshot `cfa6992e47ee16ba78c27cad8539b03bf03afeec` records source `ca0f66429bdf95552da0655eed56e34c4af67185`. Fresh main is `83cc57b65c7d316976f85977734c90eb3fbde4c6`. Twenty workload image pins are resolved; the eventual profile commit remains required for an immutable release.
- **Gateway candidate:** Coraza + CRS with Envoy. [Envoy Gateway dynamic-module documentation](https://gateway.envoyproxy.io/v1.9/tasks/extensibility/dynamic-modules/) describes a Coraza integration, but this lab selects no tested version combination yet. Compatibility spike must exercise JSON/malformed bodies, body limits, TLS, rate limiting and disabled/detect/block modes before selection. Proxy-Wasm is an alternative if the dynamic-module ABI/architecture proves unsuitable.
- **Network candidate:** Cilium in a dedicated Linux cluster, with standard Kubernetes NetworkPolicy for the initial candidate rules. [Kubernetes requires an enforcing networking implementation](https://kubernetes.io/docs/concepts/services-networking/network-policies/). Rendered YAML/JSON and API acceptance do not prove packet denial. Verify positive connections before interpreting failures.
- **Runtime candidate:** Tetragon observation followed by supported enforcement hooks. Its [enforcement documentation](https://tetragon.io/docs/concepts/enforcement/) distinguishes preventing a call from killing a process: a kill during a write need not prevent the write. Verify state after asynchronous completion. Falco detection and KubeArmor policies remain alternative profiles, not simultaneous first-release dependencies.
- **Broker permissions:** [NATS authorization](https://docs.nats.io/learn/security/authorization) separates publishing and subscribing; permission patterns follow dot-separated subject tokens. Exact account subjects are needed for the existing slash-based contract. Prove the broker decision and downstream message absence, not just a client's exit status.
- **CCC:** use [versioned CCC catalogs](https://ccc.finos.org/ecosystems/github-releases/). Proposed IDs from the design are recorded as unverified candidates with null catalog version/assessment requirements until the exact release is reviewed. Do not claim the supplied 2026.11 mapping has been verified.
- **Host compatibility:** Docker's HTTP 500 engine-proxy failure was resolved by restart. A dedicated kind cluster runs Kubernetes 1.35.0 with Cilium 1.20.5 on Linux 6.10.14-linuxkit (BTF present). The user chose to stop/preserve state-014 and retain 6 GB RAM. Default kubeconfig context is unchanged; the lab uses a separate file. Runtime hooks/LSM and agent privilege exceptions remain unverified. [Tetragon kind setup](https://tetragon.io/docs/getting-started/install-k8s/) calls for a suitable host `/proc` mount, which must be addressed in the node configuration before its integration.

## Completed compatibility slice

Standalone Envoy 1.40.2 with [Coraza proxy-Wasm 0.6.0](https://github.com/corazawaf/coraza-proxy-wasm/tree/0.6.0) passed a local TLS mode comparison using bundled CRS (observed version 4.14.0). The archive hash matched the publisher's release digest. Coraza core is 3.3.3 per that release's source. This is a compatibility result, not a production-ready version recommendation: vulnerability assessment, tuning, body/size limits, rate limiting, backend-route bypass checks and Kubernetes gateway integration remain required. Network and Restricted admission probes passed separately. No additional product or CALM integration is needed for these checks.

The supplier must provide runtime/language support, kernel/architecture requirements, install privileges, hooks and intervention timing, exact claims, failure behavior, rule/training procedure and telemetry access before candidate integration can be designed.
